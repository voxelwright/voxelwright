In use: the guide to harbor-api

Install Configure Deploy Roll back Read the logs

Install

harbor-api is one small server. It needs Node 22 and a place to keep its queue. Nothing else has to be running before it starts.

pnpm add harbor-api
pnpm harbor init

The second line writes a file named harbor.toml beside your package file. Everything the server reads at start is in that one file.

If the install stops with a message about the queue, the folder it names does not exist yet. Make it and run the line again.

Configure

Open harbor.toml. The port, the name of the project and the branch to follow are at the top. Leave the rest as it is until something asks for a change.

A project follows one branch. A push to that branch starts a build, if “Deploy on push” is on. With it off, nothing happens until someone presses Deploy.

Secrets are not kept in the file. They are read from the environment, so the file can be shared with the whole team.

Mina keeps one file for fogline's staging server and one for the live one. They differ in two lines.

Deploy

Press Deploy, or push to the branch the project follows. The build clones the branch, installs what it needs, runs the tests, and makes an image.

A build that fails changes nothing: what was live stays live. The log says which step stopped and why.

A build that passes is swapped in once its health check answers. The swap takes less than a second, and requests already on their way are finished by the old build.

The last three builds are kept, so the one before is always at hand.

Roll back

Press Roll back to put the build before this one live again. It is the same swap as a deploy, the other way.

Rolling back does not undo a change to the data. If a build changed the shape of a table, read its migration notes before going back past it.

Ada wrote those notes for every build that has them. They are linked from the build's own page.

Read the logs

Every build keeps its log. The newest line is at the bottom, and the time at the start of each line is the server's own.

A line that starts with Test names the file that was run. A line that starts with Layer is a part of the image being made.

Logs are kept for thirty days, then removed with their build.
