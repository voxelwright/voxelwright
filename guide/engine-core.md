The core is the crate in `engine/core`. It decides what every cell of the world is, applies edits, and moves what comes loose. The page's workers, the mover and the shared world process all load the same build of it, `engine/page/core.wasm`. Read [the engine](/engine) first for where it sits.

## Build it

`npm run core` in `engine/` runs `engine/core/build.mjs`, which builds the crate for `wasm32-unknown-unknown` with SIMD and bulk memory (`engine/core/.cargo/config.toml`) and copies it to `engine/page/core.wasm`.

- **Same bytes everywhere.** The build writes source paths as `/rustc`, `/cargo` and `/core`, so the served file names no one's home folder and two machines build the same bytes.
- **Cached by source and compiler.** When `engine/core` is committed and clean, the build is kept in `~/.village/engine/core-cache` under the tree's hash and the `rustc` version, and a new worktree copies it instead of building. A `core/` with changes is always built and never kept. `--no-cache` builds anyway.

## Concepts

- **Kind** (`Kind` in `engine/core/src/tree.rs`). A `u16`. The low byte is the material and its flags. The high byte is a colour from one shared palette of 256. Kind 0 is air. `engine/core/src/kinds.rs` names the materials and flags.
- **Sector.** 64 cells a side (`SIDE`), `CELLS` cells in all. `tree::encode` writes a sector as a tree of words, described in [worlds as cells](/cells).
- **Scratch** (`engine/core/src/scratch.rs`). The dense 64³ array a sector is built in before it is encoded.
- **Edit** (`Edit` in `engine/core/src/lib.rs`). `Ball`, `Runs`, `Rows` or `Fine`. `fill_of` makes a sector by running the place's rules (`city::make`), then applying the edits that reach it in order.
- **Level** (`lod` in the code). The core makes a sector at any coarseness. At level `lod` a cell stands for 2^lod finest cells each way.
- **Bodies** (`engine/core/src/bodies.rs`). Boxes of cells that came loose. They fall, collide via the spatial broadphase (`engine/core/src/broadphase.rs`) with persistent `ManifoldCache` contact warm-starting (`engine/core/src/solver.rs`), and either turn back into world cells at rest or—for persistent rigid debris (`Body::persist_sleep`)—sleep in connected simulation islands with zero CPU cost until disturbed. `Bodies` also drives time-sliced `SupportJob` queues (`budget_ops = 50_000`), per-cell water buoyancy and dynamic-body fire/extinguishing coupling (`water.rs`, `fire.rs`), 6-DOF joints with automatic voxel-anchor invalidation (`joints.rs`), 13-bone active ragdolls emitting `POSE` (wire tag `14`, `ragdoll_id` + 17 `u32` words packing the 67-byte `ragdoll::pack_pose` buffer), projectiles/occluded shockwaves (`ballistics.rs`), and multi-bounce thermal beams (`beams.rs`). Living things and people's bodies are bodies with a motor (`engine/core/src/bodies/living.rs`). Rolling vehicles also track per-wheel (`detached_wheels`) and body-panel (`detached_panels`: hood, trunk, left/right doors) detachment with structural health—disabling a sheared wheel's `Foot` suspension ray and returning `DetachedPart` specs to spawn independent tumbling bodies—plus front/rear `TowingHitch` anchors and `ram_carve_impulse` thresholds for heavy ramming through brittle walls. Moving bodies can also be carved and sliced voxel-by-voxel in place (`engine/core/src/bodies/carve.rs`). The Cleave (`cleave_wedge`) cuts a 2.5-cell kerf along a wedge of a plane through the world and through moving bodies, lets go what the cut left unheld (`support::release`, one `SETTLE` box over each tile of the cut, up to 16, nearest the eye first), and lifts every piece above the sheet off it (`CleaveHang`: up over 0.2 s of real time, held to 1.2 s, then let go sliding and tipping). `hang_tick` runs on real time, so slow motion does not slow the hang; it writes no records, so poses reach the page in `bodies_advance`'s `MOVES` (keep calling it, with `dt` 0 if the world is stopped). The kerf cuts terrain as a blast does (only water is left). `capture_orbit` takes up to `HOLD` (1,000) loose bodies out of the solver and carries them round a point; `capture_fling` lets them go at most `OUT` (150) per `advance`, the outermost first. Held bodies are out of the solver while it steps: no gravity, no contacts. `set_pose` puts a body back from outside (Time Rewind). A cut of reach 500 cells through the city takes about 0.3 s native (reach 950, about 1 s), mostly in making sectors and asking what came loose.
- **Hull** (`engine/core/src/bodies/hull.rs`). What one rolling vehicle is to another: the rectangle round its cells at each height, so the cabin and the boot are in it and the air over the bonnet is not. Other pairs of bodies meet cell by cell. A car is a hollow shell, so two cars meet as hulls and are pushed apart one way: the way their boxes overlap least, or, when one is more than 0.5 m inside the other (`INSIDE`), back the way it came in. Up and down only when they share under 40% of the lower one's height (`OVER`), so a car is not lifted onto the one it rear-ends. Severe impacts deform the hull box inward via `Hull::crush_local` (preserving a 55% cabin survival floor) in sync with `engine/page/deform.ts` (`crushDepthForImpact`).
- **Joints** (`engine/core/src/joints.rs`). Decoupled 6-DOF constraint, motor, and rope/cable/winch solver operating over `SolverBody` adapters (`id == 0` or `inv_mass == 0.0` is the static world). Supports `Fixed`, `Hinge`, `Ball` (with elliptical swing-cone, twist limits, and 3-axis PD drive), `Slider` (prismatic with Coulomb friction and linear motor), `Distance` (unilateral slack ropes/cables and motorized winches), and `Spring6Dof`. Uses Erin Catto TGS-Soft compliance (`bias_rate`, `mass_coeff`, `impulse_coeff`), persistent warm-starting (`0.85 * prev_lambda`), XPBD soft position projection, zero-bias velocity relaxation, `wasm32` `simd128` (`f32x4`) 4-wide batching (`dot4`, `cross4`, `quat_rotate4`, `solve_distance_batch_4`), force/torque break events (`JointEvent::Broken`), and Teardown-style `VoxelAnchor` invalidation (`invalidate_world_cells`, `invalidate_body_cells`). Welds (`FixedJoint`) can be plastic: past `yield_torque` the angular impulse is capped, the weld bends, and `evaluate_plastic_yield` keeps the bend for good (`rel_rot` moves, `yielded_angle` grows) until it snaps at `break_bend`. A `break_on_pull` weld breaks on tension at `break_force` and on shear or compression at `PUSH_SHARE` (2×) that. `calibrate_and_arm` ports Small Magic's settle-and-arm: it settles a structure with unbreakable welds, reads each weld's standing force and torque, and arms it by a `WeldRule` (`MORTAR`, `GRAIN`, `JOINERY`, `RIVET`, `BOLT`, `STONEWORK`, `PUTTY`, `FOOTING`) at a margin over that load, so a structure stands under its own weight and fails along its load paths. `snapshot_impulses` / `restore_impulses` carry warm-start impulses across a rewind or rebuild.
- **Dynamic fire and extinguishing** (`engine/core/src/fire.rs`). In addition to static `Ground` fires, `Fire` tracks burning local cells on moving `Body` instances (`BodyFire`, ignited via `ignite_body` and stepped via `step_dynamic_bodies`). Fire spreads across adjacent burnable voxels inside a body (favoring world-up), chars or removes burnt-out cells (`BurntBodyCell`), couples bidirectionally with static `Ground` fuel cells, and emits dynamic flame world positions into `FIRE`. Shallow water deeper than 0.05 cells, sea level, and active rain (`rain_intensity`) quench both static (`extinguish_in_water`) and dynamic flames and emit `SteamPuff` positions.
- **Water surface and per-cell buoyancy** (`engine/core/src/water.rs`). `Water::surface_at` combines the 2.5D shallow-water heightfield with an optional global sea plane to return `(water_surface_y, flow_vel_xz)`. `Water::compute_buoyancy` samples submerged body cells (striding large bodies to stay under 0.05 ms/body) to produce displaced-water buoyancy (`RHO_WATER = 1.025` against `kinds::weighs`, plus upright trapped-air buoyancy via `enclosed_hull_air_cells` that floods when inverted), center-of-buoyancy righting torque, flow-current push, and quadratic linear and angular water drag.

## The interface

The core has no generated bindings. Every call from outside is a `#[unsafe(no_mangle)] pub extern "C" fn` at the end of `engine/core/src/lib.rs`, over one instance's own memory. An instance does one thing at a time. Data passes through memory in two patterns:

- **Write in.** A `*_room(n)` call (`edits_room`, `bay_room`) returns an address. The caller writes `n` values at that address in `memory.buffer`, then makes the call that reads them. The edits in the room stay until `edits_room` is called again, and `make_sector`, `merge_rows` and `world_edit` all read them.
- **Read out.** A call returns a count, and a second call returns the address of the result: `make_sector` then `tree_words`, `merge_rows` then `merged_words`, `bodies_advance` then `bodies_words`.

Ask for the address after any call that may grow memory, because the buffer moves when memory grows. `engine/page/worker.ts` shows the whole pattern.

The exports fall into groups by prefix:

## The edit format

Edits travel as `Int32Array` words, one edit after another, and `read_edits` parses them:

| First word | Edit | Then |
| --- | --- | --- |
| `0` | `Ball` | `x, y, z, radius, kind`. Kind 0 is a blast. |
| `1` | `Runs` | `n`, then `n` rows of `x0, x1, y, z, kind` |
| `2` | `Rows` | as `1`, for rows that `merge_rows` produced |
| `3`, `4` | `Fine` | as `1`, in cells of a quarter (`3`) or an eighth (`4`) |

Any other first word is read as `1`. Input from outside is read without harm: a truncated edit ends parsing, and no kind read from outside carries the `FINE` flag. The page builds these words in `engine/page/edits.ts` (`ball`, `rows`, `fineRows`, `stream`).

## Invariants

- Same edits in the same order give the same cells on every machine. The town, the land, the Bay and fire are computed from rules and hashes. Bodies are not bit-exact across machines, which is why in a shared world the world process decides them for everyone.
- A sector made at a coarser level shows what the finest copy holds wherever a row has been (`fill_of`).
- The memory layout is private to each build. Plugins and pages call exported functions and never read the core's memory by offset, except for the documented results above.

## Check a change

```sh
(cd engine/core && cargo test --release)                       # the core's own tests
npm --prefix engine run core                                   # build core.wasm
npm --prefix engine run check                                  # the engine's checks
```

A core can be swapped into a running server without a restart: build it, then `POST /core/look`. Each world process starts the new module and replays the kept edits. Bodies in flight are lost.
